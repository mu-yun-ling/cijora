# Cijora · 此间絮语

**此间絮语** 是一个可以自己设计智能体、连接模型、把交谈中的点滴留成共同回忆的本地 AI 对话应用  
英文名`cijora`没有特殊含义，单纯音译。

界面使用原生 HTML / CSS / JavaScript，后端使用 FastAPI 与 SQLite。没有前端构建步骤，也不依赖在线字体、CDN 或远程脚本。

## 功能

- **自定义智能体**：手动填写设定，或描述想法，让 AI 生成可以继续修改的角色草稿。
- **流式聊天**：逐步显示回复，支持停止生成、失败重试、重新生成、搜索、改名及导出。
- **模型设置**：在页面中填写 API 地址、模型名和 API Key，支持 OpenAI 兼容接口及本地服务。
- **AI 日记**：空闲后合并整理共同回忆，按智能体和日期保存；支持指定日期重新整理、查看原始对话来源和 Markdown 导出。
- **纸质书房界面**：手绘房间背景、纸面聊天气泡与小鹿素材；聊天区使用清晰的纸面与更大的文字；顶部书本按钮可随时展开或收起今日手记。
- **本地保存**：会话与日记按空间隔离，模型密钥在本地加密保存，设置接口不返回密钥。

## 运行

推荐 Python 3.11，也已在现有 Python 3.8 环境测试。

```bash
python -m venv .venv
# Windows
.venv\Scripts\activate
# macOS / Linux: source .venv/bin/activate

pip install -r requirements.txt
python run.py
```

重复启动时会识别已运行的 Cijora，直接打开现有网页。端口被其他程序占用时会提示换端口。

服务就绪后会自动在默认浏览器打开 [http://127.0.0.1:8520](http://127.0.0.1:8520)。在“设置”中配置模型，然后开始聊天。默认仅监听本机地址。可用 `python run.py --port 8530` 指定其他端口，或加 `--no-browser` 只启动服务。

首次进入会创建一个本地空间。请收藏带 `book` 标识的完整页面链接；它用于找回你的空间，持有同一链接的人可以访问同一空间。

不需要编辑源码或提供环境变量即可在界面配置模型。`.env.example` 只用于可选的初始配置与数据目录设置。

## 角色的说话方式

闲聊像发消息，长短随内容变化，允许口语、碎片句、少标点，以及只回几个字、一个标点或表情符号；不按长度轮换，不强塞语气词。先回应正在聊的事，不机械安慰、总结和追问；写作、教学和分析按需要展开。只说有烦恼时先听是什么事，讲清楚后回应具体内容，不默认转成帮助邀约。AI 起草角色主要写身份、关系、关注点、性格里的矛盾和说话节奏，不把直率写成训人、把关心写成持续指导。报喜不核验，事情办妥后不追加待办；有明确求助时再认真展开。

已有角色可在聊天顶部点击编辑，切换到“让 AI 帮我设计”，再点“打磨现有设定”。原设定会自动填入作为参考，生成后可以修改，保存才生效。自己写过的角色不会被自动重写；未修改的旧版默认助手会使用新的聊天风格。旧对话中先前的回复也会影响语气，想比较新风格可以开一段新对话。

聊天界面不显示开场推荐，直接输入消息即可。回复按具体话题展开，不固定两句或两段，也不把用户的话换个说法当成回应。模型本身的表达能力也会影响最终效果。

聊天使用精简的通用规则，角色对白用 `<dialogue_examples>` 单独标记为虚构的声音参考，不作为已发生的往事。设计器会生成不同状态和节奏的对白。当前会话已经在聊天历史里，日记引用不会再重复注入同一会话的原文；其他会话的记忆仍保留说话人归属。

官方 `https://api.deepseek.com` 的 `deepseek-flash` 聊天默认明确关闭思考模式。可在“设置 → 回复偏好”开启“聊天时开启深度思考”；开启后不发送无效的温度参数。这个选项只用于官方 Flash 的聊天请求，不改变其他兼容接口、角色设计或日记整理的模式。没有该选项的旧设置也默认关闭聊天思考，无需重新填写密钥。

## 日记如何工作

聊天成功保存后先等待停聊 10 分钟，再把这段对话合并整理；同一角色同一天最多每小时自动更新一次。等待期间继续聊天会顺延，不会每句话都调用模型。手动“整理这一天”立即执行，不受等待和自动限频限制。关闭自动日记会取消尚未开始的自动整理。应用重新启动时，会补齐今天和昨天未完成的记录。应用关闭期间不会执行任务。

日记详情中可以单独删除日记，即使来源对话已经移除也能删除。删除不影响聊天记录；该角色当天的日记不会再自动重建，已在运行的旧整理结果也不会恢复它。保留了对话时，仍可手动“整理这一天”重新生成。

日记通常60～140字，一两小段，最多240字，只挑一个值得留下的瞬间，写角色回看时的想法，不按聊天顺序复述问答。日记写我们之间的回忆：说过的话、互相的回应、一起讨论或明确约定的事。人设单独作为文风和性情参考传入，不作为事件证据；角色独自讲的个人故事也不能扩写成共同经历。主观感想不存入作为长期记忆的摘要。用户分享的经历记成“你跟我说”，双方参与的虚构情境只记成“我们一起编过”。每篇日记保留实际引用的消息来源，可以核对原话。引用不存在的消息或只引用角色单方面自述时，不覆盖原有日记。没有对话的日期不会生成故事。长对话会先分段归纳，再生成当天日记。

日记整理与角色设计会调用你配置的模型，产生相应费用；自动日记可以在设置中关闭。AI 的理解和叙述可能不准确，可以查看来源并重新整理。

新对话使用日记记忆时，优先读取带说话人标记的原始消息：用户经历仍属于用户，角色的回应不等于角色亲历。旧日记原始对话不可用时，摘要会标注代词归属及无法核对的状态后作为参考。新生成的摘要使用“用户……”明确当事人，角色错认的经历不能作为事实写入记忆。

## 数据

默认保存在 `data/private/`：

- `notebook.sqlite3`：智能体、会话、日记与设置。
- `vault.key`：用于解密本机保存的模型密钥。请和数据库一起保管，丢失后需要重新填写模型密钥。

不要公开分享上述文件、真实 `.env` 或带空间标识的链接。这个版本用于本机个人使用，随机空间链接不等同于多用户账号认证；公网部署需要另行加入认证、HTTPS 与访问控制。

Windows 下兼容系统代理的 HTTP CONNECT 配置，保留显式代理协议与环境变量优先级，保持证书校验。

## 测试

```bash
python -m unittest discover -s tests -v
```

测试使用临时数据和模拟模型，不会发送私人对话，也不会消耗真实模型额度。

主动检查真实模型时，可运行 `python devtools/smoke_live.py`。它使用临时数据库，验证角色草稿、流式回复和日记三条链路，会产生正常模型调用。

## 目录

项目根目录是包含 `run.py`、`requirements.txt` 和 `src/` 的这一层 `chatbot/`。安装依赖和启动程序都在这一层执行。

```text
chatbot/
  README.md               项目说明
  requirements.txt        Python 依赖
  .env.example            可选配置示例
  run.py                  本地启动入口
  src/
    api.py                API、会话范围与网页服务
    store.py              数据库与事务
    services.py           智能体设计、聊天上下文与后台日记
    diary_queue.py        日记任务调度、合并与限频
    provider.py           通用模型接口与流式输出
    models.py             输入及生成结果校验
    vault.py              本地密钥加密
    llm/transport.py      代理兼容与连接管理
    web/                  前端页面、样式与交互
  tests/                  离线回归测试
  devtools/smoke_live.py   可选真实模型测试
```
